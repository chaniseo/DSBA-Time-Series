결측이 존재하는 시계열(ETTh1)에 대한 장기 예측 파이프라인. 제공된 스켈레톤 노트북의
제공 셀을 한 줄도 수정하지 않고, 호출부가 요구하는 계약에 맞춰 전 구성요소를 직접 구현했다.

| 항목 | 값 |
|---|---|
| 과제 | ETTh1 96시간 입력 → 96시간 다변량 예측 |
| 최종 모델 | `DRLinear` (Decomposition + channel-wise Linear) |
| 테스트 MSE | 0.4144 (표준화 공간) / 참조 baseline 0.4668 |
| 계절나이브 대비 skill | +0.288 |

## 2. 데이터 조달 — `inject_missing.py`가 존재하는 이유

> **반드시 먼저 읽어야 할 항목이다.**

과제 명세는 *"기존 벤치마크 데이터셋(ETTh1)에서 인덱스 및 결측치 추가하여 전달"* 이라고 했으나
별도 전달 파일이 없었고, 담당자 안내는 *"공개 데이터셋이니 직접 다운로드"* 였다.

공개 ETTh1을 전수 검사한 결과 명세가 말하는 오염 상태가 아니었다.

| 검사 | 공개 ETTh1 |
|---|---|
| 결측치(NaN) | 0개 |
| 인덱스 컬럼 | 없음 |
| 시간 간격 | 17,419개 전부 정확히 1시간 — 불규칙 구간 0개 |
| 중복 타임스탬프 | 0개 |

특히 요구사항 1-7(*간격이 달라지는 시점은 데이터셋으로 구성되지 않도록*)은 gap이 하나도 없으면
**구현해도 작동을 증명할 수 없다.** 따라서 명세 조건을 재현하는 주입 단계를 별도로 두었다.

**주입 모듈은 파이프라인과 완전히 분리되어 있다.** `data_provider.py`는 `inject_missing.py`를
import 하지 않고 정답 mask도 읽지 않는다. 명세의 *"결측치 여부는 사전에 공개하지 않음"* 에 따라
파이프라인은 오염 위치를 데이터에서 스스로 탐지한다.

### 주입 내역 (seed=42, 재실행 시 MD5 동일)

| 유형 | 내용 | 간격 변화 |
|---|---|---|
| (A) 인덱스 컬럼 | `Unnamed: 0` — 삭제 후 연속 재부여 | 아니오 |
| (B) 값 결측 | MCAR 3% + 연속 블록 12개(3~24h), 총 3,866셀 | 아니오 |
| (C) 행 삭제 | 블록 8개(6~48h) + 산발 10개, 총 199행 | 예 |

(A)를 연속 재부여한 것은 의도적이다. 인덱스가 `1800 → 1801`로 매끄러워도 `date`는 15시간 점프하므로,
**인덱스 컬럼을 시간축으로 믿으면 gap을 영원히 발견하지 못한다.**

## 3. 데이터 분석 요약 (요구사항 1-1 ~ 1-3)

### 가장 중요한 발견 — `isna()`는 0이지만 결측은 대량 존재

원본 ETTh1 자체에 **NaN이 아닌 형태로 위장된 결측**이 있었다.

| 패턴 | 근거 |
|---|---|
| **매월 31일 = 24시간 전 컬럼 고착** | 14일 중 14일(100%). 그 외 날은 0/711 |
| 2016-12-05 12:00~12-07 | 6개 부하 컬럼 동시에 0.000, 약 66시간. OT만 정상 변동 → 측정값이 아니라 placeholder |
| 2017-07-23~07-29 | LUFL/LULL 141시간 고착 |

연속 상수 구간 탐지(`(s != s.shift()).cumsum()`)로 찾았다. 전력 부하가 소수점까지 동일한 값으로
수십 시간 지속되는 것은 물리적으로 불가능하다.

### 그 밖의 분석

| 항목 | 결과 | 전처리·설계에 미친 영향 |
|---|---|---|
| **정상성** | 전 컬럼 ADF p<0.05 + KPSS p≤0.01 → 차분정상. 1차 차분 후 둘 다 정상 | 차분 대신 윈도우 정규화 검토 |
| **주기성** | ACF lag24=0.940, FFT(추세제거) 최상위 24.0h | `window_size=96`(4일) 타당성 확인 |
| 주간 주기 | 요일별 OT 편차 0.85도(std의 10%), MSTL seasonal_168 기여 1.1% | 주간 모듈 불필요 |
| **시계열 분해** | OT: trend 0.967 지배 / HUFL·MUFL: seasonal 0.71~0.74 지배 | 채널별 독립 가중치 근거 |
| **이상치** | IQR1.5로 HUFL 10.5%·MUFL 11.5% 검출 → 과탐 | 왜도 −1.4~−1.6 + 역조류(음수 부하) 때문. **삭제 금지, winsorize** |
| **분산 레짐** | OT 후반기/전반기 std 0.635, HUFL 1.39. rolling std 3.8~5.7배 변동 | train/test 분포 상이 → baseline의 val 0.376 vs test 0.467 격차 원인 |
| **상관** | HUFL↔MUFL 0.987, HULL↔MULL 0.930 / OT는 전부 ≤0.224 | 유효↔유효, 무효↔무효로 묶임(물리적 타당) |

> ADF와 KPSS는 귀무가설이 반대이므로 **반드시 함께** 봐야 한다. ADF만 보면 "정상"이라고 잘못 결론낸다.
> statsmodels의 KPSS p값은 [0.01, 0.10]으로 clipping되므로 `0.01`은 "≤0.01"로 읽어야 한다.

## 4. 전처리 설계 (요구사항 1-2, 1-7)

```
CSV 로드
 → [1] 인덱스 컬럼 탐지·제거      이름이 'Unnamed'이거나 값이 등차수열이면 행번호
 → [2] 시간축 정리                중복 제거, 정렬
 → [3] 은닉 결측 복원             6h 이상 상수구간 / 4개 이상 컬럼 동시 0 → NaN
 → [4] segment 분할               간격 ≠ 기준주기인 지점에서 끊음        (1-7)
 → [5] 시간순 분할                train 0.7 / val 0.1 / test 0.2, 겹침 없음
 → [6] 3단계 위계 보간            (segment × split) 블록 내부에서만
 → [7] Scaler                     train 구간에만 fit                     (누수 방지)
 → [8] 시간 특성                  timeenc=0 → 정수 (learned embedding용)
 → [9] 윈도우 인덱스 생성          segment·split 경계를 넘지 않는 것만    (1-7)
```

### 요구사항 1-7이 구현된 곳

```python
brk = dates.diff() != step        # '간격이 달라지는 시점'
seg_ids = brk.cumsum()            # 끊길 때마다 +1 → 연속 구간에 같은 번호

if seg_ids[s] != seg_ids[s + need - 1]:
    continue                      # 시작·끝의 segment가 다르면 간격을 넘은 것 → 제외
```

`seg_id`는 증가만 하므로 양 끝만 비교해도 중간이 전부 같음이 보장된다. `O(1)` 검사로 충분하다.

### 3단계 위계 보간 — 근거 기반 채택

요구사항 1-2(결측 처리)와 1-7(간격 제외)은 **책임이 다르다.** NaN을 못 채웠다고 윈도우를 버리면
1-2의 책임을 1-7에 떠넘겨 학습 데이터가 불필요하게 증발한다(실측: 46.3% 손실).
따라서 결측은 끝까지 채우고, 윈도우 제외는 간격 변화에만 적용한다.

| tier | 방법 | 대상 | 근거 |
|---|---|---|---|
| 1 | 선형 보간 (≤3h) | 짧은 구멍 | 앞뒤 값을 잇는 것이 최적 |
| 2 | 계절 나이브 (±24h, ±168h) | 긴 구멍 | ACF lag24 = 0.940 |
| 3 | 양방향 보간 + 중앙값 | 블록 가장자리 | 최종 안전망 |

정답 mask로 실측 검증 (주입 위치를 알고 있으므로 복원 품질을 정량 평가할 수 있다):

| 전략 | 전체 RMSE | point(3,641셀) | block(225셀) |
|---|---|---|---|
| 선형만 | 1.3772 | 1.0358 | 3.9022 |
| **선형+계절 (채택)** | 1.3947 | 1.1768 | 3.3181 |

전체 평균은 point 결측이 94%를 차지해 지배당한다. 유형을 나누면 **block 구간에서 계절 나이브가 15% 우수**하다.
tier1이 먼저 실행되므로 point 결측은 계절 보간의 영향을 받지 않는다.

> 주의: point 결측의 RMSE 차이는 은닉 결측 구간과 겹친 셀 때문이다. 그 구간은 "정답" 자체가
> 아티팩트(평평한 값)라 비교가 무의미하다. **block 비교만 유효한 신호다.**

## 5. 로더 검증 — 참조 구현과의 동치성 증명

스켈레톤 노트북 cell-15에는 출제자가 실행한 출력이 남아 있었다: `12003 / 1551 / 3293`.

**깨끗한 원본에 동일 설정을 적용해 이 세 숫자를 정확히 재현했다.**

```
TEST 1  원본 + 품질처리 OFF  →  12003 / 1551 / 3293   (완전 일치)
TEST 2  오염본 + 품질처리 ON  →  10173 /  956 / 2490   (19.2% 감소)
        인덱스 컬럼 'Unnamed: 0' 제거 (확인)
        은닉 결측 +2,710 복원 (선언 3,866 → 총 6,576) → 보간 후 잔여 0
        gap 18개 / segment 19개 → 간격을 넘어 제외된 윈도우 3,029개
TEST 3  배치 (B,96,7)/(B,96,7)/(B,96,4)/(B,96,4), NaN=0, train만 shuffle=True
```

우연히 세 숫자가 일치할 확률은 없다. **분할 방식(겹침 없는 시간순)과 윈도잉 로직이 참조 구현과
동일함을 증명**하며, 동시에 요구사항 1-7이 실제로 3,029개를 걸러냈음을 보인다.

> 행을 **1.14%** 지웠는데 윈도우는 **18.6%**가 무효가 된다(약 16배 증폭).
> gap 하나가 최대 `window+pred−1 = 191`개 윈도우를 오염시키기 때문이다.

## 6. 모델 `DRLinear` (요구사항 2-1)

공개 구현을 복사하지 않았다. **1단계 EDA 관측에서 각 구성요소를 역산**해 직접 설계했다.

| EDA 관측 | 설계 결정 | 실측 결과 |
|---|---|---|
| ① OT 후반기 std 0.635배, rolling std 3.8~5.7배 변동 | RevIN | +0.0070 손해 → 제거 |
| ② OT는 trend 0.967 / HUFL은 seasonal 0.712 지배 | 추세·계절 분해 후 각각 선형 사상 | 채택 |
| ③ HUFL↔MUFL 0.987이나 OT는 전부 ≤0.224 | 채널별 독립 가중치 | −0.0051 이득 |
| ④ ACF lag24=0.940, `embed_type='learned'` | 미래 시각 임베딩 | +0.0070 손해 → 제거 |
| ⑤ 요일 편차 std의 10%, seasonal_168 1.1% | 주간 모듈 없음 | (안 넣은 것도 근거 있는 결정) |

최종 구성: `individual=True, use_revin=False, use_time_bias=False` — 130,368 params

> 이름의 `R`(RevIN)은 **설계 단계에서 검토한 구성요소**를 가리키며 최종 구성에는 포함되지 않는다.
> ①·④가 실측으로 반증되어 비활성화했고, 구현은 ablation 재현을 위해 남겨두었다.
> 이름을 유지한 것은 `saved_model/` 아래 실험 디렉터리·체크포인트와의 대응을 깨지 않기 위해서다.

### 차원 변화 (요구사항 2-2)

`B`=batch, `L`=96, `P`=96, `C`=7, `T`=4

```
x_enc                                      (B, 96, 7)   인코더 입력
x_mark_enc                                 (B, 96, 4)   과거 시각   [미사용 — 관측 ⑤]
x_dec                                      (B, 96, 7)   label_len=0 → 전부 0
x_mark_dec                                 (B, 96, 4)   미래 시각   [미사용 — 관측 ④]
─────────────────────────────────────────────────────────────────────────────
 ↓ replicate pad (12, 12)                  (B,120, 7)   zero pad면 양 끝 추세가 왜곡됨
 ↓ AvgPool1d(kernel=25, stride=1)
decomp → trend                             (B, 96, 7)   이동평균
decomp → seasonal                          (B, 96, 7)   원본 − 추세
─────────────────────────────────────────────────────────────────────────────
 ↓ permute                                 (B,  7,96)   채널을 앞으로
 ↓ einsum('bcl,clp->bcp', ·, W)                         W: (7, 96, 96) 채널별 독립
ChannelWiseLinear → seasonal               (B,  7,96)
ChannelWiseLinear → trend                  (B,  7,96)
─────────────────────────────────────────────────────────────────────────────
 ↓ 두 성분 합산 + permute                    (B, 96, 7)
output                                     (B, 96, 7)   c_out = 7
```

선형층 가중치는 `1/96`(균등 평균)으로 초기화했다. 무작위 초기화 대신
"최근 96시간 평균"이라는 의미 있는 지점에서 출발시켜 수렴을 앞당기는 것이 목적이다.

검증셋 전체(956 윈도우) 기준 학습 전 MSE는 다음과 같다.

| 학습 전 상태 | MSE |
|---|---|
| DRLinear 초기값 (`1/96` 균등 평균) | 0.5858 |
| 마지막 값 반복 | 1.0685 |
| 계절 나이브 (직전 24h 반복) | 0.4292 |

초기값이 "마지막 값 반복"보다는 낫지만 계절 나이브보다는 못하다.
초기화는 **수렴 속도를 위한 것이지 성능 주장이 아니다.**
학습 후 최종 성능이 계절 나이브를 넘어서는지는 §7의 skill score로 판단한다.

## 7. 결과 (요구사항 4-1)

### ablation — 학습률 스케줄이 아키텍처보다 중요했다

30 epoch, 오염본, 동일 테스트셋(2,490 윈도우).

| 구성 | params | `lradj=type1` (주어진 config) | `lradj=cosine` |
|---|---|---|---|
| **individual만** ← 채택 | 130,368 | 0.4464 | **0.4144** |
| 최소 구성 | 18,624 | 0.4438 | 0.4196 |
| individual + RevIN | 130,382 | 0.4516 | 0.4214 |
| RevIN만 | 18,638 | 0.4509 | 0.4265 |
| indiv+RevIN+TimeBias | 131,717 | 0.4527 | 0.4285 |
| *참조 baseline* | *18,624* | *0.4668* | — |

구성요소 순효과 (각각 두 조건에서 독립 측정 → 부호가 일치하므로 고유 효과):

```
individual : RevIN有 −0.0051 | RevIN無 −0.0051   →  이득
RevIN      : indiv有 +0.0070 | indiv無 +0.0070   →  손해
TimeBias   :         +0.0070                      →  손해
```

**`type1`에서는 결론이 뒤집혀 보였다.** 학습 부족으로 파라미터가 많은 쪽이 불리해져
`individual`이 해로운 것처럼 나왔다. **스케줄과 모델 용량은 함께 판단해야 한다.**

> `clean` 대조군(깨끗한 원본으로 학습)은 위 표에 **의도적으로 넣지 않았다.**
> 오염본을 쓰지 않으므로 테스트 윈도우가 3,293개가 되어 같은 축에서 비교할 수 없기 때문이다.
> 모델 설정은 `individual + RevIN`으로 표의 세 번째 행과 동일하게 맞췄으므로,
> **`clean`(0.4397) vs `individual + RevIN`(0.4214)** 이 데이터 오염의 영향을 보는 짝이다.
> 단 테스트 표본이 다르므로 이 역시 참고치다. 결과는
> `saved_model/forecasting_ETTh1_96_96_clean{,_cosine}/`에 있다(type1 0.4624 / cosine 0.4397).

## 8. 한계점 및 개선 방향 (요구사항 4-3)

**① 주어진 config의 `lradj='type1'`이 학습을 조기에 중단시킨다**
매 epoch lr을 절반으로 → 10 epoch에 1e-7, 20 epoch에 1e-10. 30 epoch 중 실질 학습은 약 10 epoch뿐이다.
cosine으로 교체 시 **전 구성에서 5~7% 개선**. `early_stopping_count=20`도 30 epoch 기준으로는
사실상 작동하지 않는다. → cosine annealing 또는 `ReduceLROnPlateau`.

**② RevIN이 이 데이터에서는 역효과다 (+0.0070)**
설계 의도는 분포 이동 대응이었으나 실측은 반대였다. RevIN은 *"예측 구간의 수준 = 입력 윈도우의 수준"*을
가정하고 되돌리는데, OT는 2년간 40°C → 10°C로 단조 하락하므로 입력 평균이 미래 평균보다 체계적으로 높다.
**분포 이동에 대응하려던 장치가 오히려 편향을 고정시켰다.**
→ 역변환 시 추세 외삽 반영, 또는 학습 가능한 수준 보정.

**③ 예측이 보수적이다 (평균 회귀)**
전체 편향 −0.0201, 마지막 24h −0.0355. MSE 손실은 조건부 평균을 학습하므로 변동 폭을 과소 추정한다.
`outputs/eval/01_forecast_examples.png`에서 육안으로 확인된다.
→ 분위수 손실로 구간 예측, 또는 변동성 항 추가.

**④ 예측 지평이 길수록 급격히 악화** — 1h 0.1397 → 96h 0.4673 (3.3배).
→ 다중 해상도 입력, horizon별 가중 손실.

**⑤ 데이터 자체의 한계**
- 2년치라 연간 주기를 2회만 관측 → 추세와 계절이 분리되지 않는다.
- 원본 ETTh1의 월말 고착 아티팩트를 본 파이프라인은 결측 처리했으나 참조 baseline은 그대로 학습했다.
- gap 제외로 테스트 표본이 달라 MSE 직접 비교가 제한된다.

**⑥ 평가 지표의 함정** — 위 MAPE 항목 참조.
